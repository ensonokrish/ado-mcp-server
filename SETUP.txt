============================================================
ADO MCP Server - Setup Guide
============================================================
A generic MCP server for Azure DevOps work item management.
Works with any ADO organization and project.

Prerequisites
-------------
- Node.js 18+ installed
- VS Code with GitHub Copilot Chat

Steps
-----

1. Clone the repo
   git clone https://github.com/ensonokrish/ado-mcp-server.git
   cd ado-mcp-server

2. Install dependencies & build
   make install
   # or, if you prefer to run the steps manually:
   # npm install
   # npm approve-scripts keytar
   # npm run build

3. MCP config is auto-generated
   After build, .vscode/mcp.json is auto-created in this repo with the
   correct path. No manual editing needed.

   To install the MCP config into another workspace:
   make install-mcp TARGET="C:\path\to\your\workspace"

   This auto-detects the server path based on where you cloned the repo.
   If mcp.json already exists in the target, it merges without overwriting.

4. Generate an ADO PAT
   - Go to https://dev.azure.com/<your-org>/_usersSettings/tokens
   - Create token with scopes:
     - Work Items: Read, Write, Manage
     - Project and Team: Read

5. First connection (one-time)
   Run the interactive setup wizard:

   make first-connect

   It will prompt you for:
     1. Organization name   - your ADO org (e.g., 'DFIN', 'Contoso')
     2. Personal Access Token - your ADO PAT
     3. Default project      - your ADO project name
     4. Profile name         - a short name to recall later (e.g., 'myorg')

   Credentials are saved to your system keychain.
   PAT never needs to be entered again.

6. Use in VS Code Chat
   - Ctrl+Shift+P -> "MCP: List Servers" -> Start ado-mcp-server
   - In chat, first connect to ADO:
     "connect with profile <your-profile>"
   - Then you can query, create, update work items:
     "show my work items"
     "create a story for..."
     "close ticket 12345"

   NOTE: You must run "connect with profile <name>" once per chat session.
   The MCP server needs to authenticate before any other tool will work.
   If you get "Not connected" errors, run connect again.

7. Disconnect
   In chat: "disconnect"
   Or from terminal: make disconnect

============================================================
GitHub Import Usage
============================================================

1. Create a GitHub Personal Access Token (one-time)
   a. Go to https://github.com/settings/tokens
   b. Click "Generate new token" → "Generate new token (classic)"
   c. Give it a name (e.g., "ado-mcp-server")
   d. Set expiration as needed
   e. Select these scopes:
      - repo → read:org    (to access organization project boards and repository issues)
      - project             (read and write GitHub Projects v2)
   f. Click "Generate token" and copy it (shown only once)

   Fine-grained token alternative:
   a. Go to https://github.com/settings/personal-access-tokens/new
   b. Set repository access to the repos you want to import from
   c. Under "Permissions" select:
      - Issues: Read and write
      - Projects: Read and write
   d. Generate and copy the token

2. Save your GitHub token to the keychain (one-time, run in terminal)

   make connect-github

   This wizard prompts for your token with masked input (shows * only),
   verifies it against the GitHub API, then saves it to Windows Credential
   Manager. The token never passes through the LLM.

3. Connect in VS Code chat (once per session)
   In chat: "connect_github"
   No token needed — loaded silently from keychain.

2. Browse GitHub issues before importing
   "list github issues for owner: myorg repo: myrepo"
   "list github issues for owner: myorg repo: myrepo label: bug state: open"

3. Browse a GitHub Projects v2 board
   "list github project items for owner: myorg project_number: 5"
   (project_number is the number in the URL: github.com/orgs/myorg/projects/5)

GitHub Project Work Management
-------------------------------

1. Configure the Q4 Project profile after connecting GitHub:

   "configure github profile profile_name: ensono-cloudops-q4
    organization: dfinsolutions project_number: 52
    default_repository: <approved-repository>
    allowed_repositories: [<approved-repository>]"

2. Read the live Status values before creating work:

   "get github project context profile_name: ensono-cloudops-q4"

3. Create and manage GitHub-native work items:

   "create github work item title: ... work_type: story status: Backlog"
   "create github work item title: ... work_type: task parent_issue_number: 123"
   "set github work item status repo: <approved-repository> issue_number: 123 status: In progress"
   "close github work item repo: <approved-repository> issue_number: 123"

4. Migrate ADO work only after a reviewable preview:

   "preview ado to github migration work_item_ids: [12345] repo: <approved-repository>"
   "migrate ado to github work_item_ids: [12345] repo: <approved-repository> confirm: true"

   A filtered preview is also supported and never performs an unbounded scan:
   "preview ado to github migration iteration_path: <ADO iteration path>
    work_item_type: Engineering Story repo: <approved-repository>"

   Migration leaves ADO items open by default. Set close_ado_after_migration: true
   only after GitHub records and board state are verified.

   Parent links are stored as durable Markdown references for compatibility with
   GitHub Enterprise configurations that do not expose native sub-issue APIs.

4. Preview an import (no ADO item created)
   "import github issue owner: myorg repo: myrepo issue_number: 42 preview_only: true"
   Review mapped fields — title, description, labels → tags, assignee.

5. Import to ADO (prompts for ADO fields)
   "import github issue owner: myorg repo: myrepo issue_number: 42
    assigned_to: Vanapilli Dinesh
    area_path: SRE Operations and BAU\Cloud Operations\Ops\Ensono - AD
    iteration_path: SRE Operations and BAU\2026\Ensono SRE\Q3
    tags: AD; 2026 - Q3 - SRE
    parent_id: 485377"

   All ADO field overrides are optional — only title and description
   are auto-mapped from GitHub. All other fields must be provided.

   NOTE: You must be connected to both ADO (connect) and GitHub
   (connect_github) before importing.

Notes
============================================================
- PAT is stored in your system keychain (Windows Credential Manager)
- No secrets are stored in files
- After first connection, use profile_name to reconnect
- Multi-project support: pass project parameter to any tool
- Multi-profile support: save different orgs/projects as profiles

============================================================
Dynamic Intelligence
============================================================
No configuration files needed — everything is auto-detected.

On connect, the server detects:
- Story-level work item type (Engineering Story, User Story, PBI, etc.)
- Current sprint/iteration from project settings
- Product tags from recent work item history
- Active features/epics from the board
- Assignee patterns from the last 90 days of items
- Board column counts by state

This enables:
- Auto-suggest parent feature based on title
- Auto-suggest assignee based on historical patterns
- Duplicate detection before creating items
- Spell-check on all titles (auto-corrects common typos)
- Dynamic product tag validation on create

Works with any ADO process template (Agile, Scrum, CMMI).

============================================================
Security Posture
============================================================
Designed security-first — appropriate for regulated environments.

1. OS Keychain Credentials
   PAT stored exclusively in OS keychain (Windows Credential Manager
   or macOS Keychain). Never written to disk, env vars, or logs.
   Only the last 4 characters are ever displayed in audit logs.

2. Prompt-Injection Defence
   All tool responses are scanned by scrubToolResponse() before
   reaching the LLM. Patterns like "ignore all previous instructions",
   HTML injection, script tags, and system prompt overrides are
   detected and replaced with a safe redaction message.
   Source: src/security/scrub.ts

3. Full Audit Trail
   Every tool invocation is logged to logs/audit.log — timestamp,
   tool name, redacted arguments, success/failure, and execution time.
   10 MB x 10 rotation files. Complete traceability for compliance.
   Source: src/security/audit.ts

4. Scoped PAT Permissions
   PAT should be created with minimum required scopes:
   - Work Items: Read, Write, Manage
   - Project and Team: Read
   No repo, pipeline, or admin access needed.
